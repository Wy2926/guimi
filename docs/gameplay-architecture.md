# 封神肉鸽：核心玩法与架构

当前从技能测试 demo 转为正式玩法的第一阶段：先把「人物决定战斗风格、法宝决定攻击形态、属性与异常形成联动、天命改变触发规则、进化改变动作」做成最小闭环。不是完整内容版，也不宣称复刻 DNF 的数值或全部异常规则。

本期沿用原竞技场、角色模型、原三式普攻、五件法宝模型与执行器、伤害结算、成长卡池和 HUD；不新增技能图、组合解释器、全局事件总线或另一套战斗框架。美术继续遵循 [东方神话 · 通透灵韵](art-direction.md)，不因人物神通更换或增加模型。

## 一局的五个能力系统

| 系统 | 负责什么 | 本期内容 | 运行时归属 |
| --- | --- | --- | --- |
| 人物神通 | 法宝驾驭偏好与被动规则 | 哪吒·三头八臂；已获得飞剑 +1 把、绫带 +1 连锁目标 | `RunProgression.divinity`／`artifact_count`，原法宝执行器读取 |
| 法宝 | 主要攻击形态 | 诛仙剑阵、混天绫、照天印、定海珠、太极图 | `skill_definitions`／`skills` 与现有法宝执行器 |
| 属性与异常 | 持续伤害、控制和跨法宝联动 | 四元素通道、八异常状态；来源固定在法宝定义 | `SkillDefinition` 声明，敌人持有状态，玩家结算反应 |
| 天命词条 | 改变触发规则 | 火印应劫 | `fate_definitions`／`fates`，明确的直接命中入口 |
| 终极进化 | 组合门槛后的攻击质变 | 诛仙剑阵·贯阵 | `evolution_definitions`／`evolutions`，原飞剑路径分支 |

初始携带哪吒神通与一级诛仙剑阵，其余四法宝在升级时领悟。基础近战是人物固有动作，不再作为独立技能领悟。生命、攻击、防御、移动等基础修行保留作数值调校手段，不算第六个能力系统。

已移除旧斩击、裂环斩、厉鬼的技能资源、技能栏与成长池。人物沿用原三式普攻；三头八臂不绑定五式八击或范围翻倍，也不复制动画。内部资源 ID 与现有模型路径保留，避免因改名产生重复资源。

## 人物神通：哪吒·三头八臂

采用[《封神演义》第七十六回](https://zh.wikisource.org/zh-hans/封神演義/卷076)的三头八臂题材，把多臂驾驭器物转译为法宝数量与连锁容量加成。加成规则是本作改编，不将小说设定等同宗教教义；不要求角色真的长出额外头臂。

- 默认常驻被动，入场及重开直接影响法宝数量；没有按键、持续时间、冷却、变身循环或角色附体粒子。人物模型、原三式普攻、普攻命中区域与选敌范围均保持原样。
- **诛仙剑阵 +1 把飞剑**：五级基础剑数 2/3/4/5/6，哪吒实际为 3/4/5/6/7；新增的一把也是原模型沿真实路径独立命中，不把一次伤害拆成两行数字。上限 7 把，不无界叠加。
- **混天绫 +1 个不同连锁目标**：五级基础 3/4/5/6/7，哪吒实际为 4/5/6/7/8；仍只有一条绫带，沿原路径多访问一名目标，不克隆绫带或再次打同一目标。施放时快照连锁容量，升级不延长当前这一轮。
- 数量统一经过 `RunProgression.artifact_count(id, rank = -1)`，执行器、HUD 和升级卡共用；原 Resource 的基础数组不变。未获得的法宝仍返回 0；不会因被动提前解锁混天绫，也不会增加照天印、定海珠或太极图的数量／范围／频率。绫带在途升级时，HUD 区分本轮快照容量与下轮新容量。
- 不增加全局伤害、攻速或范围。增加的真实法宝接触仍可参与原有属性异常与天命联动；人物近战保持无属性，不消费感电或碎冰。
- 旧「莲身续战」依赖限时神通，已删除资源、成长池入口及击杀续时逻辑，不保留无效词条，也不在此轮凭空替换成另一种天命。
- 按当前要求保留角色模型，不把「制作三头八臂实体模型」列为待办或验收缺口。

## 五件法宝：固有属性，不做全局附魔

| 名称／内部 ID | 固有伤害与异常 | 攻击方式及成长 | 组合职责 |
| --- | --- | --- | --- |

| 太上老君·太极图／`taiji_aura` | 光属性魔法；感电 3 秒 | 随身两仪八卦阵周期脉冲，基础周期 1.2 秒 | 给另一法宝的直接命中准备有次数上限的连锁传导 |

每次攻击只有法宝定义中的一个元素；无属性跳过抗性修正。`BattleStats` 不再包含人物攻击元素或元素强化数组，成长池没有火／冰／光／暗附魔卡或元素攻击强化卡。敌人的四元素抗性仍保留。

法宝上限均为五级，原有倍率成长与数量／范围成长仍在，但组合变化不依赖单纯增伤：混天绫会携火，感电产生旁路命中，诅咒把死亡变为传播机会，贯阵直接改写飞剑出手路径。

飞剑每次选定目标、开始一段攻击路径时快照该段伤害系数与是否走进化路径；升级不改写正在进行的这一段，下一段重新选目标时才读取新等级与进化。它不是整套人物数值的冻结快照。升级只补充新增飞剑，不替换在途实例。

- **照天印**：取自[第六十四回](https://zh.wikisource.org/zh-hans/封神演義/卷064)罗宣祭印的情节。复用 `assets/effects/zhaotian_seal/` 印体、15 块碎片及 `SealShatter` 原生动画；投影崩裂不表示原著法宝自毁。
- **定海珠**：旧「雷缚珠」更名，以[第四十七回](https://zh.wikisource.org/zh-hans/封神演義/卷047)赵公明的法宝为题材。现有紫黑宝珠、暗域牵引、诅咒属于明确的游戏改编，不声称原著定海珠是暗属性黑洞。复用 `assets/effects/thunder_orb/`，不复制或改名模型文件。
- **太极图**：用户所称八卦图对应已有的两仪八卦阵，统一名为太上老君·太极图，参照[第六十一回](https://zh.wikisource.org/zh-hans/封神演義/卷061)。复用 `assets/effects/taiji_aura/` 玉质阵心、八卦刻纹、反向旋转与四层粒子；光与感电是本作改编。

上述资产的 `.blend` 源文件、GLB、概念图、建模脚本与现有材质／着色器全部保留。原美术规范中的「雷缚珠」指同一套历史资产，不构成另一件可选法宝。

## 属性与八异常

借鉴 DNF 的火、冰、光、暗攻击与异常区分，但不照搬其数值表。属性是命中的固有通道，异常是目标身上的有限时状态，两者不能混为同一种全局人物属性。

| 异常 | 首版规则 | 当前可用来源 |
| --- | --- | --- |
| 出血 `bleed` | 每 0.5 秒持续伤害，基础系数 0.12 | 诛仙剑阵 |
| 中毒 `poison` | 每 0.5 秒持续伤害，基础系数 0.16 | 框架已支持，本期没有中毒法宝 |
| 感电 `shock` | 3 次传导次数；另一法宝直接命中时消耗一次 | 太极图 |
| 灼烧 `burn` | 每 0.5 秒持续伤害，基础系数 0.18 | 照天印；混天绫可携带原有火种 |
| 冰冻 `freeze` | 打断动作、停止主动行动；可被特定法宝命中碎冰 | 框架已支持，本期没有冰法宝 |
| 束缚 `bind` | 停止自主移动，但仍可近身攻击，也可受既有法域牵引 | 混天绫 |
| 眩晕 `stun` | 打断动作、停止主动行动 | 框架已支持，本期没有独立施加法宝 |
| 诅咒 `curse` | 本身不造成持续伤害；目标死亡时传播原有持续异常 | 定海珠 |

持续伤害沿用原法宝的物理／魔法／固定类型与元素，读取该类型攻击力、目标防御及抗性；不再抽取暴击或闪避，不触发新的直接命中反应或火印应劫，实际击杀仍走共用死亡与经验路径。同类持续异常刷新剩余时间，不重置伤害时钟，不无界叠层。

控制不是永久锁死：同一种控制在生效期间不续时，结束后有 1 秒同类恢复免疫；精英控制时长乘 0.35，首领免疫冰冻／束缚／眩晕。定海珠原有减速与牵引仍由已有法域系统处理，不新增一套运动状态。

## 先实现明确、有限的连锁

| 组合 | 真实行为变化 | 限制 |
| --- | --- | --- |
| 照天印 → 混天绫 | 绫头命中原始灼烧目标后记住火种，后续真实路径接触把火传给下一批目标 | 继承火种来源及递减的剩余时间，不重置为完整持续时间；同轮仍只访问不同目标 |
| 太极图 → 另一法宝 | 后续直接命中消耗一次感电，向 3 米内最多 3 名其他敌人传导光属性魔法伤害 | 0.30 魔攻系数，每目标 0.35 秒反应间隔；太极图不靠自身脉冲消费自己施加的感电 |
| 定海珠 → 持续异常 → 击杀 | 被诅咒者死亡时，不论击杀来自直接、次生或持续伤害，都将自身原始灼烧／出血／中毒传播到 3 米内最多 3 名敌人 | 保留来源和剩余时间；传播状态标记为次生，不能继续靠诅咒接力传播，单个状态最多传播一代 |
| 冰冻 → 火或物理／固定法宝 | 消耗冰冻，目标自身与 3 米内最多 3 名敌人受到一次冰碎魔法伤害 | 0.35 魔攻系数；本期正常构筑没有冰冻施加源，保留为已实现的扩展接口 |
| 混天绫束缚 → 贯阵飞剑 | 已获得进化时，飞剑优先束缚目标，跳过绕行蓄势，直接贯穿沿线目标 | 保留有界的飞行旅时与收招尾拍；沿途真实胶囊接触，每次突刺每敌一次；非束缚目标仍走原路径 |

次生伤害不会重新附加原法宝异常、启动即时感电／碎冰反应或触发火印应劫；额外祭出的火印也带次生标志。但次生火印、感电传导和冰碎仍使用共用命中数学，可以暴击或闪避，不代表必中。诅咒的死亡传播仍检查被击杀者身上的原始持续异常，仅已经传播为次生的状态不能再次传播。这是可验证的具体规则，不是「任意属性自动生成任意反应」的解释器；也没有火引爆诅咒这一条规则。

## 天命与终极进化

| 类型 | 名称／ID | 出现条件 | 改变的规则 |
| --- | --- | --- | --- |
| 天命 | 罗宣·火印应劫／`crit_seal` | 已获得照天印 | 非火印的直接命中暴击可向存活目标请求额外火印，触发间隔 1.5 秒；原执行器检查 8.5 米 × 范围系数的距离与在途数量，次生火印不附灼烧，也不再次触发火印应劫 |
| 进化 | 通天教主·诛仙剑阵·贯阵／`swords_pierce` | 诛仙剑阵五级 + 混天绫三级 | 改变对束缚目标的飞剑路径，直接贯穿；不是再增加一层伤害倍率 |

天命和进化各只领悟一次，满足前置条件才进入升级池，真正选择时再检查一次门槛和已获得状态。名字中的「火印应劫」「贯阵」是游戏规则，不作为原著术语宣称。

## 对局与成长

沿用既有 2.5D 正交竞技场和十分钟生存循环：移动／自动近战 → 法宝自动施放与异常联动 → 击杀掉落经验 → 暂停三选一 → 达到组合门槛后取得天命或进化 → 击败终局首领。普通、冲锋、远程、精英和首领继续复用原刷怪与预警逻辑。

经验需求仍为 `round(14 + 6 × (等级−1) + 0.8 × (等级−1)^1.5)`。超额经验保留，连续升级逐次选卡；选择不回写共享 Resource。

三选一优先提供已满足的进化、未获得法宝、可用天命，剩余位置由原法宝升级／基础修行池补齐；没有候选重复、满级卡或元素附魔卡。物理攻击卡支持人物固有近战，魔法／独立攻击卡按已持有的法宝伤害类型出现。选择使用当时重新生成的有效候选，不能通过伪造卡片字段随意写入 `BattleStats`。

基础上限沿用原调校范围：生命 620，三攻 300，双防 100，暴击 75%，暴伤总倍率 300%，闪避 40%，吸血 12%，攻速 ×2，范围 ×1.8，冷却时长系数最低 0.4，移速 8，拾取半径 7。生命成长只补新增上限，不每次升级回满。

HUD 沿用既有容器和卡片，改为「一个人物神通 + 五件法宝」六格：神通显示「常驻被动」「飞剑+1 · 绫链+1」，不显示激活按键或倒计时；法宝和升级卡显示应用神通后的实际数量，以及固有属性与异常、等级和执行状态，并列出已领悟天命与进化。暂停面板显示基础数值与四元素抗性，不再显示人物附魔或元素强化。

## 伤害口径

所有来源继续通过 `DuelFighter` 的伤害入口与 `DamageRules.calculate`，接收者负责无敌、实际扣血、控制和一次死亡事件。

1. 直接命中先判闪避，再按物攻／魔攻／独立攻击乘该攻击系数。
2. 物理／魔法乘 `100 / (100 + max(对应防御, 0))`；固定伤害跳过双防，但不是无条件真伤。
3. 有元素时乘 `clamp(1 − 目标该元素抗性, 0.15, 3)`；无属性不读取元素抗性。
4. 允许暴击的直接伤害在暴击成功时乘暴伤总倍率，再四舍五入，有效命中最低 1 点。
5. 接收者返回实际扣血、闪避、免疫、暴击和击杀；只有有效接触才能进入异常和天命规则。

持续伤害与次生伤害都复用同一套防御／抗性数学。只有 `periodic = true` 的持续伤害不再抽取暴击／闪避，接收者的死亡或免疫检查仍有效；`secondary = true` 只关闭命中后的原法宝异常附加、即时反应和火印应劫，并不关闭暴击／闪避或真实击杀事件。次生祭印、感电和冰碎因此仍可暴击、被闪避或被免疫。

吸血按实际扣血结算，沿用原每秒最大生命 12% 的恢复预算，不把过量伤害算成恢复。敌人本系抗性、对立弱点和法宝异常是不同机制，不用单纯抗性增减替代连锁反应。

异常状态存在敌人实例，神通定义及能力所有权存在 `RunProgression`；人物神通没有额外的激活状态或计时器。没有额外单例管理器、平行属性集合或跨帧全局事件队列。来源以弱引用保存，死亡、停用、胜负、重开沿用原清理路径。暂停时战斗节点、法宝路径／补间、冷却、异常时间和在途攻击一起冻结。

## 特效覆盖与 Blender MCP 建模核对

前一轮清单中的异常与联动缺口已在原有模块内补齐；这仍是资源与代码覆盖，不是画面验收。区分「多层表现」与「多重粒子」：模型、Shader 刀光、范围线和灯光可以形成多个视觉层，但不等于存在多个粒子发射层；下表的粒子层数按实际 `GPUParticles3D` 发射器计数。

### 分层预算

- 每种异常两层各 8 个粒子槽，共 16 槽；单敌全部八异常合计 128 槽。控制免疫是单个限时标记，不堆叠、不加粒子。
- 每把飞剑增加两层合计 16 槽，保留原 14 槽闲置光尘；闲置与突刺发射按真实动作切换。七剑没有新增实体或光源。
- 混天绫保留原四层 132 槽；首次携火才增加两层 20 槽，同一轮不重复分配。接触粒子沿用原短生命周期。
- 瞬时反应每件 16–40 槽、0.48–0.80 秒；Feedback 同时最多 32 个新反应根节点，包含贯阵和天命重音。饱和时省略新的装饰，不改变任何命中、状态或连锁。新增效果不为每名受害者加灯光。
- 以上是代码中的节点与槽位限制，不是 GPU 帧率或视觉拥挤度验收。渲染尺寸、透明排序与同屏可读性仍需要明确授权的可见实玩检查。

### 哪些必须建模，哪些不需要

- **按当前要求，没有必须新增的 Blender MCP 建模项。** 人物保留 `assets/characters/Knight.glb` 的骨架／头部／动作和 `Rogue.glb` 的服饰网格；三头八臂只提供法宝被动，不制作三头、多臂、额外骨架或变身动画。
- **本轮无需 Blender 已完成的内容：** 八异常的文字／粒子／轮廓、火星／毒点／血气、符记、光环、电弧、传火／诅咒连线、简单碎霜和贯穿重音。复用现有 Godot 粒子、材质、网格路径、范围环与反馈入口；没有为每种状态建立独立模型资源。
- **已有五法宝不需要重新建模。** 全部有现成可用资产；改名、改规则、调整尺寸或路径不产生新的建模需求。只有将来明确要求新的实体器形、精雕冰壳或真实破碎拓扑时，才将那部分新增网格／模型动画交给 Blender MCP；不把这种可选美术规格列为本期必需。

## 验收和下一阶段

自动化只能运行 `scripts/run.ps1 -Verify`（默认 `--headless`），或显式带 `--headless` 的 Godot 导入／测试；不弹出游戏或编辑器窗口、不抢焦点。已有混天绫专用演示在自动检查时同样必须附带 `-Headless`。

核心验收关注：五法宝目录和命名、无元素卡／全局元素字段、默认三头八臂仅为已获法宝加量且不改变模型／普攻／范围、法宝固有异常、持续伤害时钟、控制免疫、跨法宝感电、携火、诅咒有限传播、天命防递归、进化门槛与真实贯穿接触、暂停与清理，以及原满技能负载。已有模型、路径、原生动画和表现复用检查继续保留。

无窗口验证只证明逻辑、资源加载与生命周期，不能作为画面、音频、GPU 性能或十分钟构筑平衡的验收。本期没有冰／毒法宝、其他可选人物、完整进化树、局外养成、装备背包或新建模；后续内容在已有边界里按具体需求接入，不提前建空框架。
